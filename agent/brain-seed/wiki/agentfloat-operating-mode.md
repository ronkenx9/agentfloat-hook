# AgentFloat — Operating Mode

The owner of funds controls how much autonomy the AI orchestrator has. This file is the single source of truth — edit it to change behavior. The agent re-reads it every epoch.

The deterministic promoter still gates real capital regardless of mode. Operating mode controls the *shadow-deployment* and *proposal-approval* layer above it.

---

## Modes

| Mode | What the AI does | What the human does |
|------|------------------|---------------------|
| `watch` | Proposes only. Writes markdown to `proposals/`. | Approves every proposal manually. |
| `review` | Proposes, then waits N hours. Auto-approves if no rejection. | Vetoes anything they don't want. |
| `auto-shadow` | Auto-approves and deploys whitelisted action types (typically `parameter_variant`). Novel strategies stay pending. | Reviews only novel proposals. |
| `autonomous` | Handles everything subject to guardrails below. | Sets policy, reviews periodically. |

The deterministic promoter is always the floor — no AI mode lets the orchestrator promote a shadow to active. That's earned by score history.

## What each field means

| Field | Meaning |
|-------|---------|
| `mode` | One of `watch` · `review` · `auto-shadow` · `autonomous` |
| `auto_approve_after_hours` | In `review` mode: how long to wait before auto-approving a pending proposal if not rejected. `null` disables. |
| `auto_approve_action_types` | In `auto-shadow` mode: list of action types that auto-approve immediately. Others remain pending. |
| `max_proposals_per_day` | Hard cap on total proposals generated by orchestrator. Prevents runaway loops. |
| `max_strategies_registered` | Refuse to auto-deploy new shadow strategies if registry already has this many. |
| `tvl_cap_usd` | If vault holds more than this in USD, drop to `watch` mode regardless of config. `null` = no cap. |
| `pinned_strategy_ids` | These strategies cannot be retired by the AI under any mode. Useful for keeping a baseline floor. |
| `blocked_action_types` | Action types the AI is forbidden from proposing at all. |
| `require_security_audit_for` | Action types that must pass `v4-security-foundations` before auto-approval (Phase 3). |
| `veto_window_hours` | Per action type: how long a proposal sits in `pending_review` before auto-approval kicks in (mode-dependent). |
| `chain_actions_allowed` | Chain-scoped allowlist. On X Layer mainnet (chain 196) the AI is bounded to safe actions only: `register_strategy`, `retire`, `scoring_change`, `no_action`. New Solidity contracts (`new_strategy`, `parameter_variant`) cannot ship to mainnet without human review and an audit — the AI's job there is to *select* from a pre-audited library, not deploy fresh code. |

## How to change modes

1. Edit the JSON block above
2. Save the file
3. The approver re-reads on the next epoch — no restart

Document mode changes in today's journal so other agents understand why behavior shifted.

## Mode-switching cheat sheet

**"I want full control"** → `mode: watch`. Nothing auto-approves.

**"I want the AI to do safe stuff while I sleep"** → `mode: review`, `auto_approve_after_hours: 8`, leave `auto_approve_action_types` empty. Every proposal waits 8h; if you don't reject, it ships.

**"I trust parameter tweaks but not new contracts"** → `mode: auto-shadow`, `auto_approve_action_types: ["parameter_variant", "retire"]`. Parameter variants auto-deploy as shadows; novel strategies stay pending.

**"Full autonomy with guardrails"** → `mode: autonomous`. Everything except items in `blocked_action_types` proceeds. Audits still required for `new_strategy`. TVL cap kicks in if vault grows past threshold.

## Emergency stop

Set `mode: watch` and the AI immediately stops auto-approving anything. Pending proposals stay pending. In-flight on-chain transactions still complete (we don't cancel deployments mid-flight).
